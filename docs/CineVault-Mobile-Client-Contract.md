# CineVault: контракт клиентов

Этот документ фиксирует API, который должны использовать будущие Android-, TV- и iOS-клиенты. Клиенты не дублируют логику каталога, комнат или подготовки локальных файлов: всё это остаётся на сервере CineVault.

## Базовые правила

- Базовый URL берётся из настройки приложения, например `https://cinevault.example.org`.
- Все ответы и запросы — JSON в UTF-8, если отдельно не указан файл или SSE.
- При включённом `CINEVAULT_VIEWER_TOKEN` защищённые запросы передают `Authorization: Bearer <token>`.
- Администраторские импорт и загрузка файлов используют отдельный `X-CineVault-Admin-Token`; пользовательские клиенты его никогда не хранят.
- Клиент воспроизводит только URL, которые вернул CineVault. Он не извлекает, не расшифровывает и не проксирует сторонние потоки.

## Каталог и карточка

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверка доступности сервиса. |
| `GET` | `/api/catalog/index` | Индекс импортированных карточек для локального поиска и ссылок. |
| `GET` | `/api/catalog?kind=movie&page=1&page_size=24&genre=...&sort=rating` | Страница каталога. `kind`, `genre` и параметры сортировки необязательны. |
| `GET` | `/api/catalog/facets` | Список доступных фильтров. |
| `GET` | `/api/catalog/imported/{catalog_id}` | Полная импортированная карточка и её варианты воспроизведения. |
| `GET` | `/api/library` | Локальная медиатека и история просмотра. |
| `GET` | `/api/history` | История, отсортированная сервером по последнему просмотру. |

Клиент открывает фильм по стабильному `catalog_id` или локальную серию по `episode_id`; не пытается восстанавливать эти идентификаторы из названия.

## Прогресс и продолжение просмотра

```http
PUT /api/progress/{episode_id}
Content-Type: application/json

{"position": 324.2, "duration": 6400.0, "completed": false}
```

Прогресс сохраняется на событиях `pause`, `seek`, `ended` и периодически во время просмотра. При запуске клиент ждёт `loadedmetadata` выбранного видео, и лишь затем устанавливает сохранённую позицию. Это предотвращает сброс на `0:00` при смене HLS-источника.

## Совместный просмотр

Создать комнату:

```http
POST /api/watch/rooms
Content-Type: application/json

{
  "episode_id": "local-episode-id-or-empty",
  "title_id": "catalog-id",
  "target_key": "catalog-id-s0e0",
  "season": 0,
  "episode": 0,
  "position": 324.2,
  "playing": true
}
```

Сервер отвечает `{ "room_id", "share_code", "state" }`. Ссылка комнаты имеет вид `/title/{catalog_id}/?room={room_id}`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/watch/rooms/{room_id}` | Текущее состояние и начальная синхронизация. |
| `POST` | `/api/watch/rooms/{room_id}` | Команда `play`, `pause`, `seek` или смена серии: передать обновлённые `position`, `playing`, `season`, `episode`, `target_key`, `title_id`. |
| `GET` | `/api/watch/rooms/{room_id}/events` | SSE-канал. Первое событие — актуальное состояние комнаты, последующие — команды участников. |

`state.seq` строго возрастает. Клиент применяет только более новые значения; когда `playing: true`, позиция вычисляется как `position + (сейчас - updated_at)`. Перед применением состояния новому участнику надо дождаться готовности видео (`loadedmetadata`). При разрыве SSE клиент переходит на опрос `GET /api/watch/rooms/{room_id}` раз в 2.5 секунды и возвращается к SSE после восстановления.

## Офлайн для собственных файлов

Для файла из локальной медиатеки доступны только следующие операции:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/library/episodes/{episode_id}/offline-manifest?quality=720p` | HLS-плейлист и сегменты для внутреннего кэша приложения. |
| `POST` | `/api/library/episodes/{episode_id}/download` | Запустить подготовку MP4 или сразу получить статус `ready`. |
| `GET` | `/api/library/episodes/{episode_id}/download` | Опрос статуса: `idle`, `processing`, `ready`, `error`. |
| `GET` | URL из `download_url` | Получить готовый MP4 с `Content-Disposition: attachment`. |

Офлайн-кэш приложения хранит `episode_id`, выбранное качество, список сегментов и дату последней проверки. Удаление серии удаляет только этот кэш; удаление фильма — все связанные серии. Внешние embed-плееры не поддерживают MP4-экспорт.

## Что остаётся на стороне клиента

- Android/TV: ExoPlayer/Media3 для HLS и локального кэша.
- iOS: `AVPlayer` и `AVAssetDownloadURLSession` для HLS и офлайн-кэша.
- Перед переходом на следующий экран клиент сохраняет последнее известное состояние воспроизведения.
- URL комнаты, идентификаторы и прогресс — серверные данные; UI и локальный кэш можно безопасно пересоздать.
