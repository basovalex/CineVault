# Ошибка загрузки каталога на публичном домене

Пользователь подтвердил URL `cinevault-aleksandr.duckdns.org` и текст «Не удалось загрузить каталог, проверь подключение и попробуй ещё раз».

Проверено с рабочего компьютера:
- DNS домена возвращает адрес текущего сервера.
- TCP 443 устанавливается примерно за 0,17 секунды; TCP 80 тоже доступен.
- TLS с проверкой сертификата и корректным server_hostname зависает до timeout.
- Ограничение до TLS 1.2 проверено отдельно; результат записывается по факту ответа инструмента, не предполагается причиной.
- Локальные API на 8093 и 8095 возвращают 200.

Проверено через SSH на сервере:
- Caddy active, контейнер running/healthy.
- Публичный HTTPS отвечает 401 без Basic Auth, что ожидаемо для закрытого сайта.
- API каталога, discovery и facets отвечают 200, примерно 0,42–0,79 секунды, каталог 116342 карточки.
- В последних просмотренных логах 9 запросов каталога вернулись с 200; traceback не обнаружены.

В коде общий экран ошибки показывается для разных причин. Основной запрос каталога имеет abort через 15 секунд, а service worker позволяет открыть сохранённую оболочку при сетевом отказе. Поэтому видимая страница не доказывает, что TLS/API сейчас доступны. Это объясняет наблюдение, но не доказывает, что конкретный запрос пользователя оборвался ровно по той же причине.

Установленная граница сбоя: HTTPS/TLS между рабочим компьютером и сервером; причина маршрутизации/фильтрации не установлена. Нет оснований объявлять удалённым каталог или менять алгоритм рекомендаций из-за этой ошибки. Запрошены состояние VPN и проверка через независимую мобильную сеть.

В рамках диагностики защита Basic Auth/TLS не отключалась, DNS/Caddy/серверные данные не менялись. Перезапуск исправного сервера без подтверждённой причины не выполнялся.
