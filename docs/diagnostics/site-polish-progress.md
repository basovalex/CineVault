## Что сделано на этапе 5

Замер: `tests/measure_site.py --profiles phone,desktop --network 4g --cpu 4 --runs 3` через локальный стенд. «4G» здесь 1,6 Мбит/с (≈200 КБ/с), процессор ×4. Локальный стенд теперь сжимает ответы gzip, как Caddy на проде (`tools/dev_site_proxy.py`): без этого замер завышал вес скриптов и API на ~800 КБ.

| | До этапа | После |
|---|---|---|
| LCP, телефон | 10,0 с (13,3 с в начале работы) | 3,7 с |
| LCP, компьютер | — | 3,7 с |
| FCP | 2,2 с | 0,75 с |
| Вес первого экрана, телефон | 7,9 МБ | 4,9 МБ |
| CLS | 0,000 | 0,000 (компьютер 0,031) |
| INP | 72 мс | 48 мс |

Что изменено:
- Герой главной фиксируется при первой отрисовке: раньше он менялся несколько раз, пока догружались подборки, и каждый раз заново «рождал» главный элемент.
- Полный кадр героя запрашивается сразу с высоким приоритетом (уменьшенная копия на плотных экранах всё равно не считается главным элементом); полки ждут его не дольше 2,5 с (`.home-shelves.is-waiting`).
- Первая страница каталога запрашивается из `index.html` параллельно с загрузкой `app.js`; `app.js` берёт ответ, только если запрос совпадает (`takeCatalogPrefetch`).
- `hls.js` грузится через 5 с после загрузки страницы, а не сразу.
- Плитки жанров и карточки продолжения берут кадр 678×380 вместо 1344×756; постеры и плитки с низким приоритетом.
- Полки за экраном не рисуются и не грузят картинки до приближения (`content-visibility: auto`, резерв высоты 300/380 px).
- Сервер: долгий кеш для всех скриптов и стилей с `?v=` и для шрифтов, тип `font/woff2`.

До 2,5 с не хватает около секунды. Часть — особенности стенда (SSH-туннель к API, HTTP/1.1 вместо HTTP/2 на проде). После выкатки нужно проверить на проде.
