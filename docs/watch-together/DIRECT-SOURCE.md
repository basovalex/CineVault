# Собственный плеер: проверка прямого источника Alloha

## Решение пользователя

Выбран вариант 1 — собственный плеер CineVault с проверенным прямым потоком, если доступный источник позволяет его получить. Сохранение iframe как окончательное решение не выбрано. Нельзя незаметно подменить Alloha другой озвучкой или другим провайдером.

## Что проверено 2026-11-02

- Свежий player-options для «Ночи в музее» (Кинопоиск 178580) возвращает одну озвучку и валидный iframe Alloha.
- Получена актуальная HTML-страница iframe: HTTP 200, 12353 байта. В HTML нет HLS-ссылок; `fileList` содержит идентификаторы и метаданные. Embed содержит `token_movie`, `translation`, `token`.
- В текущем app.4f61d9ad.js поток загружается через `/bnsi/movies/...`, заголовок Borth и WebSocket-обмен/периодические stream-токены. Простого HTML-парсера недостаточно. Результаты не дают права считать сохранённую ссылку переносимой между устройствами.
- Android TV извлекает `player.hls.url` и заголовки внутри WebView, где разрешён document-start script. В обычном браузере сайт не имеет такого доступа к cross-origin iframe. Расширение браузера не решает сценарий телефона без дополнительной установки.
- В открытом адаптере Lampac есть отдельная ветка прямого доступа: `GET {linkhost}/direct?secret_token=...&token_movie=...&ip=...&translation=...`, опционально season/episode. Нужен **отдельный secret_token**, не обычный ключ каталога. Контракт взят из исходного кода интеграции; наличие такого доступа у текущего аккаунта и работоспособность endpoint ещё не подтверждены.
- В локальном окружении ключ каталога отсутствует, на сервере `CINEVAULT_APBUGALL_TOKEN` настроен. В проверенном `/srv/cinevault/.env` нет отдельной настройки прямого Alloha. Секреты не выводились и не переносились.

Первичный источник контракта интеграции: [Alloha.cs в Lampac](https://github.com/Chokolite/lampac/blob/main/Online/Controllers/Alloha.cs), метод Video, ветка «Прямые ссылки». Код не запускался и пакет не устанавливался. Код сторонней интеграции не является гарантией поддержки провайдером.

## Подготовленный код

`tools/alloha_direct.py`:
- требует явно настроенные HTTPS endpoint `/direct` и secret;
- принимает только server-side выбранную озвучку из известного embed;
- не принимает URL потока от пользователя и не воспроизводит скопированный cURL;
- отключает redirects запроса с секретом, ограничивает размер/таймаут;
- не передаёт requests exceptions с URL/секретом клиенту;
- нормализует HLS-варианты и субтитры, сохраняет default audio;
- возвращает `verification: provider-response-only`: это ещё не доказательство воспроизведения;
- определяет внешний IP с доверием к XFF только от настроенных proxy, цепочка разбирается справа налево.

5 unit-тестов проходят: default audio, небезопасные URL, отсутствие потока, IP spoofing, отключённые redirects, отсутствие секрета в результате и явное отсутствие конфигурации. Эти тесты используют фикстуры и не проверяют настоящий direct API.

Адаптер **ещё не подключён** к HTTP/player UI. Существующий iframe-плеер сохранён до успешной проверки нового источника. Продукт не выдаёт новый поток за работающий.

## Что требуется для следующей проверки

Нужны доступ к прямым ссылкам Alloha, соответствующий secret_token и подтверждённый endpoint из кабинета провайдера. Значения хранить в `.env`/серверном окружении, не в чате/репозитории:

- `CINEVAULT_ALLOHA_DIRECT_API_URL`
- `CINEVAULT_ALLOHA_DIRECT_SECRET`
- `CINEVAULT_TRUSTED_PROXY_IPS` — реальные адреса/сети reverse proxy; не разрешать произвольный XFF.

Без отдельного direct-доступа не обещать, что ключ каталога разблокирует собственный плеер. Публичные чужие токены из результатов поиска не использовать.

Далее проверить ответ API, master/media manifest, первый сегмент и воспроизведение HTMLVideo/Hls.js с домена сайта; CORS, поддержку Safari, IP-привязку и срок жизни URL. Ссылку получать отдельно для каждого зрителя — не раздавать всем ссылку ведущего. При смене VPN/IP обновлять источник и возвращаться на авторитетную позицию комнаты. Не проксировать весь поток через backend без отдельной оценки нагрузки и доступа.

После успешной проверки: native media adapter, настоящие readyState/buffered/waiting/canplay/seeked, один комплект host controls, только локальные guest controls, затем включение аккаунтного протокола комнаты 3 и сквозные тесты из основного задания. До этого 10–15-минутная приёмка не выполнена.
